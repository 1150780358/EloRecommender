## 一、本周工作进度

### 1）端到端建模管线实现（承接上周方案）

- 完成主管线 `src/elo_pipeline.py`（约 1,200 行）：内存压缩、业务化分层清洗、双交易表 **196 维**聚合/时序/交叉特征、两道特征筛选闸、按异常值分层十折、LGB/XGB/CatBoost 多回归 + 异常二分类 + 干净回归、Ridge Stacking 与加权融合对照、产物自动落盘；

- 自动化就位：提交后自动轮询取分并回填台账；无人值守战役脚本上线，本周含跨夜运行,夜间时段持续产出实验结果。

### 2）私榜真实标尺建立（上周计划的"衡量尺度"问题）

经 Kaggle API 取回原赛私榜 Top200 真实分数表（`outputs/private_lb_top200.json`），建立「Private 分数 → 等效名次」精确换算。**这件事立刻纠正了一个重要误判**：按公开资料粗估，我们首提成绩在铜牌线以外；用真实分数表定位后，实际已在银牌线边缘。我的体会是：这类"非建模"的度量基础设施优先级其实很高——尺子不准时，连"现在在哪、该往哪走"都会判断错。

### 3）v1→v4 四轮快速迭代

坚持"每轮只改一类东西、离线验证通过才提交"的小步纪律，四轮迭代全部有据可查：

| 版本 | 关键改动 | 离线 OOF | Private | 等效名次 / 4111 |
|---|---|---|---|---|
| v1 | 三路模型 + Ridge Stacking（自研首提） | 3.64362 | 3.61276 | ~210（银牌线边缘） |
| v2 | + 观察月锚定特征 + 干净回归后处理 | 3.64195 | 3.60974 | 114 |
| v3 | + Optuna 参数复搜终选 | 3.64228 | 3.60965 | 112 |
| v4 | + 开源移植特征（众数聚合/序列 TFIDF-SVD 嵌入/逐月透视与斜率/算术交叉）+ huber 第 4 基模型 + 3-seed 平均 | 3.63670 | **3.60759** | **69（top 1.7%，银牌区中上游）** |

从迭代数据里我读出一个明确信号：**参数调优一轮仅改善 0.00009，而特征改动动辄 0.002~0.003**。据此我把调参降级为收尾手段，资源全部转向特征——与第一周调研得出的"特征优先"结论形成闭环。

### 4）三个工程问题的定位与解决

- **训练异常变慢**：小样本下 LGB/XGB 反而慢数倍。先量化再假设：定位为 32 线程同步开销反超收益，固定 16 线程解决；
- **结果不可复现**：huber 模型两次训练结果不一致。逐折二分比对，定位为多线程浮点累加顺序不固定 × 验证曲线平坦导致早停轮次漂移，开启 deterministic 模式解决；
- **公榜严重背离**：公榜排名 1493/4111 与私榜 69 名严重不符，按方案预案直接弃用公榜，坚持离线择优。

三个问题我都按"先量化、再提假设、再做对照实验"的路子排查，而不是凭感觉换配置——这套排查方法比单个问题的解法更值得沉淀。

## 二、本周学习收获

### 1）特征的边际收益远大于调参

0.003 对 0.00009 的量级差距让我直观理解了"信息增量决定上限,参数只是逼近上限"。后续立项时，我会先问"这个改动引入了什么新信息"，而不是"还有什么参数可调"。

### 2）"不可复现"是工程问题，不是玄学

浮点累加顺序这类非确定性来源，要么用确定性开关消除，要么把自检标准从"逐位一致"降级为"统计一致"。银行场景对模型可复现的要求更严，这次排查是很好的预演。

### 3）小步迭代 + 全程留痕 = 可讲述的证据链

因为每轮只改一类东西且台账完整，v1→v4 每 0.001 的提升都能说清来源。这既是实验纪律，也是将来答辩时"建模流程"一节的底气。

### 4）自动化的复利开始显现

无人值守脚本让夜间也在产出结果，一周内完成 4 轮迭代 + 多次线上验证。吞吐靠基础设施，不靠加班——第二周把迭代速度当设计目标的决策得到了回报。

### 5）人机分工进一步清晰

本周的分工模式是"我提假设、AI 快速做对照实验"：线程开销、复现性问题都是这样闭环解决的。判断与假设由人产生，工具负责把验证做快。
