## 〇、研发环境:算力硬件与 AI 协作方式(贯穿四周)

### 算力与硬件:现有资源 vs 实际占用

| 资源 | 现有配置(共享 GPU 服务器) | 实际占用 |
|---|---|---|
| CPU | AMD EPYC 7542,32 核 64 线程 | 训练固定 **16 线程**(约全机 1/4;实测 32+ 线程在中小样本上同步开销反超收益,反而更慢) |
| 内存 | 128 GB | 2900 万行交易经列类型降精度压缩后单机全量处理,常驻远低于机器上限,无需分块/分布式;特征构建 3.7 分钟、端到端 25.3 分钟 |
| GPU | 2× NVIDIA RTX 4090(24 GB) | GBDT 主线 **0 卡**;仅 v5 异构基学习器(torch MLP×2)短时占用 1 卡 |
| 存储 | /data 7.3 TB 共享盘 | 项目全量约 **4.4 GB**(原始数据 + `outputs/` 基模型产物 + refs 开源仓库) |
| 软件环境 | conda(Python 3.11)+ CUDA torch | base 环境覆盖全部依赖;`requirements.txt` 固化版本 |

> 结论:本项目对算力的实际需求远低于机器配置——**16 CPU 线程 + 数十 GB 内存、无 GPU 依赖**即可完整复现主线结果,GPU 仅为异构模型实验的可选项。

### AI 辅助研发(Claude Code + Claude Fable 5)

全程采用 **Claude Code**(Anthropic 官方终端智能体,驱动模型为 Claude 5 家族的 **Fable 5**)作为结对研发工具,在服务器终端内直接读写仓库、执行实验。四个阶段的分工方式:

1. **调研阶段**:AI 通读 refs 下开源仓库的全部 notebook,逐仓核验"README 自述招数是否有代码证据",输出带可移植性评级的分析文档;人负责提问框架与结论把关;
2. **方案阶段**:方案文档由人给出目标与约束、AI 起草备选与权衡,经对话评审定稿;
3. **编码与实验阶段**:管线与实验脚本以结对编程方式产出(AI 写代码、人做设计决策与结果判读);**无人值守战役脚本**(特征重建→全套重训→择优提交→记录回填)由 AI 编写并跨夜自主运行,夜间时间也持续产出实验结果;
4. **文档与工程化**:任务日志、周报、泄露审计、README 由 AI 起草、人审定;Git 提交与 GitHub 推送(deploy key 安全配置)由 AI 执行。

**协作纪律(人机边界)**:方向取舍、提交判据、成绩口径由人最终拍板;AI 产出的任何特征/模型改动一律经 OOF 与线上验证后才采信;常开**多个并行会话**分别推进实验、文档与工程化,以「写前查 mtime、并入而非覆盖」的约定避免互相冲突;全部改动进 Git,可追溯可复现。

## 第 1 周(07-27 ~ 08-02):赛题调研与数据理解 —— 产出调研文档

### 一、工作进度

1. **赛题背景调研**:理解业务目标(Elo 巴西支付平台,依据持卡人历史交易预测其对商户推荐的忠诚度分数)、评价指标(RMSE)与数据构成(train/test 约 20/12 万卡、历史+新商户两张交易表共约 2900 万行、商户属性表);确认本赛 2019 年已截止,当前为 Late Submission,Kaggle 仍正常返回 Public/Private 分数但不进官方榜。
2. **Top 方案与开源代码分析**(成文 `docs/202607/31-Top方案对比分析.md`,初版核验见 `29-opensource_analysis.md`):以公开 kernel 级 baseline(基础聚合 + LGB,Public≈3.69 档)为参照,逐方案分析前排"比 baseline 多做了什么":
   - **材料摸底**:经 Kaggle 讨论区原帖与 GitHub 核实,取得 1st/5th/7th/10th/11th/16th/18th/19th/21st/22nd 及 28th/31st/55th 等十余份复盘;前 10 名中**仅 7th(senkin13)开源完整代码**,另有 21st(bestpredicts/ELO)与 63rd 两个完整代码仓,已拉取至 `refs/` 逐仓核验;
   - **Top10 逐方案要点**:1st = 离群概率软融合公式(CV +0.015)+ 行级 meta feature(target 嫁接交易行,分类器最强特征);5th = 五模型分段架构 + 两步加权 target encoding(双重 OOF 防泄漏);7th = 8 种数据集切分 + tfidf/w2v/图嵌入 + 行级 meta model(+0.005),单模 Private 3.593 可排第 3;10th = 6500 特征 + month_lag 逐月透视/未来月外推 + 82 模型农场;11th = 相关性配对造特征 + 32 模型 BayesianRidge stacking + 多分类器交集后处理;16th = KS 检验/null importance 特征选择 + 修改版三模型法;19th = 商户离群率 one-hot(与 TE 同信息源)、完全无后处理;22nd = month_lag 阈值子集重算全部特征(+0.010);
   - **21st/63rd 代码仓核验**:21st 六类特征逐一找代码证据并按可移植性分级(算术交叉/CountVector 高、TE 须折内重构、w2v/NFFM 留后续);63rd 众数聚合需向量化重写——两仓即后续 v4/v6 移植清单的来源;
   - **横向对照与频次统计**:序列嵌入(7 个方案)、大规模 stacking(6)、month_lag 深挖(4)、行级 meta model(3)为最高频增量;多项负结果互证(isotonic 有害、二层 LGB 过拟合、直接 TE 无效);识别出行级 meta model、month_lag 子集重算等明确空白;
   - **差距归因分解**:与 Top1 分差拆为特征深度(可追)、模型农场规模(边际成本极高)、私有洞察(部分可复现),据此定下"特征优先、不堆模型农场"的资源策略;
   - **通用提分手段清单**:outlier 三模型法/软融合、month_diff 近期性、purchase_amount 脱敏还原(raddar)、观察月锚定、按 outlier 分层验证、"trust your CV"纪律。
3. **官方数据文件分析与 EDA**(成文 `docs/202607/31-官方数据文件分析.md`):逐一分析官方 7 个数据文件(train/test、两张交易表、merchants、sample_submission、字段字典)的规模、字段、表间关系与质量问题,实测确认关键事实:
   - 官方仅提供数据与提交格式示例,**无 baseline 代码**;每卡直接属性极少,信息重心必须放在 2900 万行流水的聚合上;
   - target 中 outlier 共 **2,207 个(1.09%)**,全部为哨兵值 -33.219,决定了「分类+分层」的方案骨架;
   - installments 存在 -1/999 哨兵值,且与 category_3 缺失同源,应作同一缺失机制处理;
   - month_lag 是各卡不同参考月的隐藏时间对齐轴,时序特征须按其对齐而非自然月;
   - merchants 表存在 63 个重复 merchant_id,需去重规则;
   - 交易表 2900 万行的时间范围、缺失分布与内存占用摸底(为后续内存压缩设计提供依据)。
4. **验证与提交策略调研**:本赛公榜仅 30% 测试数据且历史上私榜大洗牌,多个高名次方案强调「信 CV 不信公榜」;确定后续以 OOF 为唯一择优判据,公榜只作烟雾测试。
5. **复现 baseline 代码并完成首次提交**:以调研所得开源实现为底(63rd 单文件管线的精简复现:基础聚合特征 + LGB 分层五折),端到端跑通「数据 → 特征 → 训练 → 预测 → kaggle CLI 提交 → 分数回流」全链路;确认 Late Submission 通道正常返回 Public/Private 分数,并将该成绩登记为后续所有改进的**对照基准**【baseline 分数以 `docs/submissions.md` 流水为准】;过程同时验证了环境依赖完整性与 2900 万行数据的单机可行性。
6. **产出调研文档 2 份**(开源方案分析、数据 EDA 与清洗策略),沉淀为 `docs/` 下可追溯记录;同步搭好 conda 环境、拉取数据、打通 kaggle CLI 认证。

### 二、学习收获

1. **先看赛题的"分数结构"再动手**:1.09% 的 outlier 贡献了 RMSE 的绝大部分方差 —— 拿到回归赛题先画 target 分布,识别重尾/哨兵值,往往直接决定方案骨架,比急着堆特征更重要;
2. **调研要区分"文字复盘"与"可核验代码"**:Top 方案的 README 自述常与代码实际不符,只有找到代码证据的招数才能进移植清单;对每个招数标注可移植性与依赖风险,调研文档才能直接驱动排期;
3. **用 AI 智能体做代码考古的效率跃升**:让 Claude Code 通读两个开源仓库的 16 个 notebook 并逐一核验特征证据,一天内完成了传统方式数天的调研量;但结论必须由人复核代码出处,AI 负责广度、人负责判据;
4. **匿名字段的解读方法**:通过分布形态、共现关系(如 installments 哨兵与 category_3 缺失同源)反推脱敏前语义,是处理脱敏数据集的通用技能;
5. **公榜/私榜机制**:小比例公榜 + 私榜洗牌意味着刷公榜等于过拟合 30% 样本;验证体系的可信度是竞赛第一基础设施;
6. **差距要先归因再动手**:把 0.021 分差拆解为"可追/不可追"两类后,资源自然聚焦到特征深度而非模型农场——调研的终点是资源分配决策,不是知识清单。

### 三、下一周工作计划

- 基于调研结论撰写**总体技术方案文档**:数据清洗规则、特征体系(聚合/时序/交叉三族)、按 outlier 分层的十折验证设计、多模型 + Stacking + outlier 二分类的模型架构;
- 制定**实验管理与提交纪律**:OOF 判据、提交流水档案格式、DEBUG 小样本与全量的缓存隔离;
- 规划工程结构(`src/ + scripts/ + docs/ + outputs/`)与自动化实验(无人值守训练→提交→记录回填)方案。

## 第 2 周(08-03 ~ 08-09):总体技术方案设计 —— 产出方案文档

### 一、工作进度

1. **产出总体技术方案文档**(数据 → 特征 → 验证 → 模型 → 实验管理五层),关键设计决策如下:
   - **数据层**:列类型降精度内存压缩(2900 万行交易可在单机全量处理);业务化分层清洗 —— 哨兵值按缺失机制归位(installments -1/999)、purchase_amount 线性还原、merchants 表按规则去重;
   - **特征层**:规划双交易表 **约 200 维**特征体系,分三族 —— 聚合统计族(卡×商户/类目/城市的计数、金额分布)、时序族(month_diff 近期性、月度序列的透视与斜率)、交叉族(历史表×新表的比值与差分);特征筛选用方差过滤 + 模型重要性两道闸;
   - **验证层**:**按 outlier 分层的十折交叉验证**,保证每折 outlier 比例一致;OOF 为唯一择优标准,并记录 CV-LB 偏移作为过拟合警报线;
   - **模型层**:LGB/XGB/CatBoost 多基模型 + outlier 二分类器 + 剔除 outlier 的 clean 回归,二层用 Ridge Stacking 与加权融合对照;预留 huber 损失、多 seed 平均等扩展位;
   - **实验管理**:提交前必须有离线 OOF 支撑;每次提交自动登记到流水档案(分数、改动、结论);基模型 OOF/test 预测统一落盘为 `outputs/base/*.npz`,使融合实验脱离重训、降为秒级代数运算。
2. **工程方案**:确定 `src/`(管线与实验脚本)+ `scripts/`(战役 Shell)+ `outputs/`(产物)+ `docs/`(任务日志)四目录结构;设计「特征重建 → 全套重训 → 择优提交 → 记录回填」的无人值守战役脚本,支持 nohup 跨夜运行。
3. **风险预案**:公榜不可信 → 方案中写死"纯 OOF 择优";Late Submission 无官方名次 → 计划经 Kaggle API 取回私榜 Top200 真实分数建立「Private 分数 → 等效名次」标尺;复现性 → 固定 seed、记录环境与参数。
4. **方案评审与排期**:与导师对齐方案;排定第 3 周编码与首轮提交、第 4 周深化优化的里程碑。

### 二、学习收获

1. **方案文档的价值在"决策与理由"而非"步骤"**:每个设计点写清备选项与取舍依据(如为何分层十折、为何 OOF 优先),后期实验矛盾时可回溯是假设错了还是执行错了;
2. **验证体系要先于模型设计**:CV 划分方式(分层)、判据(OOF + CV-LB 偏移)、噪声水平(折间波动)不先定义,后面所有"改进"都无法判真伪;
3. **把融合实验与重训解耦**是实验吞吐的关键设计:基模型产物落盘后,二层融合从每次 10 分钟重训降为秒级,一天可对比几十个方案;
4. **实验纪律是提交额度约束下的最优策略**:每天提交次数有限,"先离线验证、再上线确认"的门禁能把额度全部花在有信息量的提交上。

### 三、下一周工作计划

- 按方案文档实现端到端管线 `src/elo_pipeline.py`(清洗 → 特征 → 分层十折 → 多模型 → Stacking → 产物落盘),完成自研管线首次提交(v1),量化其对第 1 周 baseline 的提升幅度;
- 搭建 `submit_and_log.py` 自动提交与流水回填、战役 Shell 无人值守;
- 启动 v1→v4 快速迭代:观察月锚定特征、Optuna 调参、开源方案特征移植、huber 基模型与多 seed 平均;
- 经 Kaggle API 建立私榜等效名次标尺。

## 第 3 周(08-10 ~ 08-16):管线编码与首轮实验(v1→v4)

### 一、工作进度

1. **端到端管线编码完成**(`src/elo_pipeline.py`,约 1200 行):内存压缩、业务化分层清洗、双表 **196 维**聚合/时序/交叉特征、方差+重要性筛选、按 outlier 分层十折、LGB/XGB/CAT 多回归 + outlier 二分类 + clean 回归、Ridge Stacking 与加权融合、产物自动落盘;全量端到端 **25.3 分钟**(2900 万行交易的特征构建仅 3.7 分钟)。
2. **提交与自动化基础设施**:在第 1 周打通的 kaggle CLI 链路上,`submit_and_log.py` 实现提交后自动轮询评分并回填 `docs/submissions.md` 流水;战役脚本实现「特征重建 → 全套重训 → 择优提交 → 记录回填」全程无人值守(含跨夜运行)。
3. **私榜真实标尺**:经 Kaggle API 取回私榜 Top200 真实分数表(`outputs/private_lb_top200.json`),建立「Private 分数 → 等效名次」精确换算,纠正了基于公开资料的粗估(首提成绩实际已在银牌线,而非估计的铜牌线外)。
4. **v1→v4 四轮迭代**(每步均有离线 OOF 支撑后才提交):

   | 版本 | 关键改动 | OOF | Private | 等效名次 / 4111 |
   |---|---|---|---|---|
   | v1 | 三模型 Ridge Stacking(自研管线首提,超越第 1 周 baseline) | 3.64362 | 3.61276 | ~210(银牌线边缘) |
   | v2 | + 观察月锚定特征 + clean 后处理 | 3.64195 | 3.60974 | 114 |
   | v3 | + Optuna 终选参数 | 3.64228 | 3.60965 | 112 |
   | v4 | + 移植特征(众数聚合/序列 TFIDF-SVD/月度透视斜率/算术交叉)+ huber 第 4 基模型 + 3-seed 平均 | 3.63670 | 3.60759 | **69(top 1.7%,银牌区中上游)** |

5. **工程问题排查**:
   - LGB/XGB 小样本训练慢数倍 → 定位为 32 线程同步开销,固定 16 线程;DEBUG 与全量特征缓存隔离防污染;
   - huber-LGB 结果无法复现 → 逐折比对定位为多线程 histogram 浮点累加顺序不固定 × 验证曲线平坦导致 best_iteration 漂移,打开 `deterministic + force_row_wise` 解决;
   - 公榜排名(1493/4111)与私榜严重背离 → 按方案预案弃用公榜,改为纯 OOF 择优 + 私榜标尺换算。

### 二、学习收获

1. **性能问题优先怀疑并行开销而非算法**:小数据 + 高线程数反而更慢,是树模型训练的常见坑;先量化再调优;
2. **"不可复现"是可以逐折二分定位的工程问题**:浮点累加顺序 × 平坦验证曲线 → early stopping 漂移,这类非确定性来源要么用 deterministic 开关消除,要么把自检标准从逐位一致降级为统计一致;
3. **调参的边际收益远低于特征**(v3 仅 −0.00009 vs v2/v4 特征改动的 −0.003/−0.002),Optuna 应作收尾手段而非主攻方向;
4. **多 seed 平均是低风险稳定收益**:折平均 + seed 平均双重降噪,对高方差成员尤其有效;
5. **自动化的复利**:AI 编写的无人值守战役脚本让夜间时间也在产出实验结果,一周内完成 4 轮迭代 + 多次线上验证的吞吐靠的是基础设施而非加班;
6. **人机结对的正确分工**:AI(Claude Code / Fable 5)负责代码生成、仓库操作与批量排查,人负责设计决策、判据设定与结果判读——32 线程性能坑、huber 不可复现等问题都是"人提出假设、AI 快速做对照实验"闭环解决的。

### 三、下一周工作计划

- **深化实验**:系统验证融合层重构(校准/二层选型/异构基学习器)与增量特征族的收益;

### 二、学习收获

1. **改进的类型决定收益的真伪**(本项目最重要的发现):结构优化(融合层/异构模型)的 OOF→Private 转化率仅 2%,引入新信息(目标编码)转化率 45% —— 竞赛后期立项的前置问题应是"这个改动引入了什么新信息";
2. **Stacking 的方差陷阱**:OOF 是单模型输出而 test 是十折平均,折平均对高方差成员降噪更多,二层因此系统性高估其价值 —— v5 虚假收益的机制性解释;
3. **目标编码是高基数类别列的钥匙,但防泄漏是生命线**:裸 id 列树模型分裂效率极低,折外 outlier 率编码将其转为有序信号即成最强新特征;而 TE 折与模型 CV 折必须同套,否则折外信息漏入验证折,OOF 虚高;
4. **警惕与模型内建机制重复造轮子**:CatBoost 自带 ordered target statistics,外喂 TE 反而变差;特征重要性占比高 ≠ 信息增量,判据只能是 OOF;
5. **负结果要完整记录**:v5 的证伪日志直接指出了 v6 的正确方向,避免在饱和路径上继续消耗提交额度;失败复盘与成功记录同等重要;
6. **AI 时代研发流程的再认识**:四周实践下来,AI 智能体改变的是"广度与吞吐"(代码考古、批量实验、文档沉淀),不变的是"判据与取舍"必须由人守住——OOF 验证纪律、提交额度分配、成绩口径这些决策环节恰恰是价值密度最高的部分。

### 三、后续工作展望(实习结束后)

- **TE 键集与平滑策略继续扩展**:交易粒度时间差分布特征(a2p/p2r/p2now)、更多高基数键;
- **序列/图模型**:交易序列 GRU/Transformer 或 card-merchant 二部图嵌入,提供聚合统计无法表达的信息 —— 冲击金牌线(差距 0.00557)的候选路径;
