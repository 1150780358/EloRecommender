## 二、主要工作(8 项)

1. **竞赛调研与数据 EDA**:梳理 Top10 方案通用提分手段(outlier 三模型法、month_diff 近期性、金额脱敏还原、观察月锚定、按 outlier 分层验证);EDA 实测确认 outlier 2,207 个(1.09%,固定哨兵值 -33.219)、installments -1/999 哨兵与 category_3 缺失同源、merchants 表 63 个重复 id 等关键事实,形成调研文档 2 份。
2. **端到端建模管线**(`src/elo_pipeline.py`,约 1200 行):内存压缩、业务化分层清洗、双表 196 维聚合/时序/交叉特征、方差+重要性筛选、按 outlier 分层十折、LGB/XGB/CAT/huber-LGB 四回归 + outlier 二分类 + clean 回归、Ridge Stacking 与加权融合、产物自动落盘;全量端到端 25.3 分钟(2900 万行交易的特征构建仅 3.7 分钟)。
3. **提交与自动化基础设施**:kaggle CLI 链路打通;`submit_and_log.py` 提交后自动轮询评分并回填流水档案;两个战役脚本(`scripts/`)实现「特征重建 → 全套重训 → 择优提交 → 记录回填」全程无人值守,累计 3 场战役跨夜连续运行。
4. **私榜真实标尺**:经 Kaggle API 取回私榜 Top200 真实分数表,建立「Private 分数 → 等效名次」精确换算,纠正了此前基于公开资料的错误估计(首日成绩实际已在银牌线,而非估计的铜牌线外);此后每次提交的名次定位均为精确值。
5. **v1→v4 快速迭代**(4 轮):观察月锚定特征、Optuna TPE 复搜、开源方案移植特征(众数聚合 / 序列 TFIDF-SVD 嵌入 / month_lag 透视与斜率 / 系统性算术交叉)、huber 第 4 基模型、3-seed 平均;Private 3.61276 → 3.60759(等效 210 → 69 名)。

## 四、问题与解决

| 问题 | 定位与解决 |
|---|---|
| LGB/XGB 小样本训练慢数倍 | 32 线程同步开销所致 → 固定 16 线程;DEBUG 与全量特征缓存隔离防污染 |
| 公榜排名(1493/4111)与私榜严重背离 | 本赛公榜 30% 划分过拟合、私榜大洗牌 → 弃用公榜,改为纯 OOF 择优 + 私榜真实标尺换算 |
| huber-LGB 结果无法复现 | 逐折比对定位:多线程 histogram 浮点累加顺序不固定 × 验证曲线平坦 → best_iteration 漂移;打开 `deterministic + force_row_wise` 解决,自检改为统计一致性 |
| v5 揭示 OOF 改善不再可靠转化 | CV-LB 偏移 0.03043 → 0.02721 漂移即警报 → 判据升级为「降 OOF 且不缩小偏移」,并转向新信息路径(v6 验证有效) |
| 21st 原版 TE 存在折外泄漏 | 其 TE 折与模型 CV 折不同套,折外信息漏入验证折 → 重构为严格折内统计 + 贝叶斯平滑 + 连续键离散化,既防泄漏又保留增益 |

## 五、思考与方法论沉淀

1. **改进的类型决定收益的真伪**:结构优化(融合层/异构模型)的 OOF 收益转化率仅 2%,新信息(目标编码)转化率 45%——竞赛后期应把「这个改动引入了什么新信息」作为立项前置问题;
2. **Stacking 的方差陷阱**:OOF 是单模型输出、test 是 10 折平均,折平均对高方差成员(MLP/ET)降噪更多,二层因此系统性高估其价值——v5 虚假收益的机制性解释;
3. **高基数 id 列是聚合特征体系的盲区**:裸 id(城市/商户类目众数)树模型分裂效率极低,TE 把它们转成有序 outlier 率后成为最强新特征——TE-v2 增益的主要来源;
4. **警惕"重复造轮子"的冗余**:CatBoost 内建 ordered target statistics,外喂 TE 反而变差;特征重要性占比(新特征 gain 占 38.3%)≠ 信息增量(OOF 变差),判据只能是 OOF;
5. **负结果值得完整记录**:v5 四个方向的证伪日志直接指出了 v6 的正确方向,避免了在饱和路径上继续消耗提交额度。
