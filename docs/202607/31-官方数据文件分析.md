## 二、逐文件分析

### 2.1 train.csv / test.csv

- **字段**:`first_active_month`(首次激活月,YYYY-MM)、`card_id`、`feature_1/2/3`(匿名类别,取值个位数级)、`target`(仅 train)。
- **核心事实:每张卡的直接属性极少**——3 个低基数匿名特征信息量很低,预测能力几乎全部要从交易流水中构造。
- **target 分数结构**(全赛题最关键的数据事实):脱敏后的忠诚度分数,主体近似 0 均值连续分布;其中 **2,207 个(1.09%)为固定哨兵值 -33.219**。RMSE 对大偏差平方敏感,这 1% 的 outlier 贡献了误差的主要部分 → 直接决定「全量回归 + outlier 二分类 + clean 回归」三模型架构与**按 outlier 分层的十折验证**。
- **target 业务含义未公开**:Top1 方案推测为参考月后约两个月窗口内的某种消费回报指标;新商户表的时间窗恰与之重合,是其单位信息价值高的原因。

### 2.2 historical_transactions.csv(主战场)

- **字段**(14 列):`card_id`、`merchant_id`、`merchant_category_id`、`subsector_id`、`city_id`、`state_id`、`purchase_amount`、`purchase_date`、`installments`、`authorized_flag`、`category_1/2/3`、`month_lag`。
- **month_lag 全部 ≤0**:交易月距该卡"参考月"的月数;参考月可由 `purchase_date` 与 `month_lag` 联立推算(观察月锚定特征的来源),各卡参考月不同——**这是隐藏的时间对齐轴**,直接按自然时间聚合会混淆不同卡的观察期。
- **质量问题**:
  - `purchase_amount` 线性脱敏,可近似还原真实金额量纲(还原后聚合统计更符合业务直觉);
  - `installments` 含 **-1/999 哨兵值**,且与 `category_3` 缺失**同源**(同一缺失机制,应一并处理而非各自独立填补);
  - `merchant_id`、`category_2` 存在缺失;
  - `authorized_flag` 含被拒交易(D),被拒行为本身是信号(v5 曾做被拒画像特征族)。
- **建模地位**:285 维特征中九成以上由本表聚合而来(计数/金额分布/去重基数/month_diff 近期性/逐月透视与斜率/众数/序列嵌入);2900 万行经列降精度压缩后单机全量处理,特征构建 3.7 分钟。

### 2.3 new_merchant_transactions.csv

- **列结构与历史表完全相同**,但 `month_lag` 仅取 +1/+2:即参考月之后两个月内、在该卡**从未消费过的商户**发生的交易。
- **时间窗与 target 定义窗口重合**,单位行数信息价值远高于历史表;「新表 ÷ 历史表」的比值/差分交叉特征刻画对新商户的接受度,是稳定的强特征族。
- 注意部分卡在新表中无记录(冷启动),交叉特征需处理分母缺失。

### 2.4 merchants.csv

- **字段**(22 列):商户 id 与类目归属、匿名数值 `numerical_1/2`、近 3/6/12 个月的销售/购买量均值与活跃月数(`avg_sales_lag*` / `avg_purchases_lag*` / `active_months_lag*`)、销售等级 `most_recent_sales_range` 等。
- **质量问题**:**63 个重复 merchant_id**(需按规则去重后才能关联);`avg_*_lag*` 存在 inf/极端值需截断。
- **实测增量价值有限**:大部分信息可从交易表聚合等价获得;v6 商户侧 TE 亦被证伪(OOF 不动)。结论:低优先级辅助表。

### 2.5 sample_submission.csv / Data_Dictionary.xlsx

- `sample_submission.csv`:两列 `card_id,target`,行集合 = test 全量;仅约束提交格式,占位预测无基线意义。
- `Data_Dictionary.xlsx`:各表字段一句话说明;匿名字段(feature_*、category_*、numerical_*)仍不给业务含义,需靠分布形态与共现关系反推。

## 三、表间关系与建模范式

```
train/test(卡粒度,1 行/卡)
   │ 1 : N(card_id)
   ├── historical_transactions(29.1M 行,month_lag ≤ 0)
   └── new_merchant_transactions(1.96M 行,month_lag ∈ {1,2})
             │ N : 1(merchant_id)
             └── merchants(商户画像,需先去重)
```

建模范式:把每张卡几百至几千笔流水**聚合为一行特征向量**(本项目 196 → 285 维),再回归 target;树模型(LGB/XGB/CAT)学习特征 → 分数的映射。特征工程的信息上限远高于模型选择——这是本赛题(及同类脱敏行为流水赛题)的基本格局。

## 四、数据质量问题与处理策略汇总

| # | 问题 | 所在表 | 处理策略(本项目) |
|---|---|---|---|
| 1 | target 1.09% 哨兵值 -33.219 | train | outlier 二分类 + clean 回归 + 分层十折;不当作普通回归噪声 |
| 2 | purchase_amount 线性脱敏 | 两交易表 | 线性还原真实量纲后再聚合 |
| 3 | installments -1/999 与 category_3 缺失同源 | 两交易表 | 视为同一缺失机制,统一归位处理 |
| 4 | merchant_id / category_2 缺失 | 两交易表 | 缺失作独立类别;聚合时显式计数 |
| 5 | 参考月各卡不同(month_lag 对齐轴) | 两交易表 | 观察月锚定特征;时序特征一律按 month_lag 对齐而非自然月 |
| 6 | merchants 63 个重复 id、数值列 inf | merchants | 规则去重、极端值截断;整体降为低优先级 |
| 7 | 每卡直接属性过少 | train/test | 信息重心放在流水聚合;feature_1/2/3 仅作交叉底料与 TE 键 |
