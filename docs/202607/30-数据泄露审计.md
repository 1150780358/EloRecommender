# 数据泄露审计(Data Leakage Audit)

- **日期**:2026-07-30
- **触发**:v6 TE-v2 出现 OOF −0.0043 / Private **+0.0059** 的反向背离
- **结论**:**存在一处一级泄漏,已定量坐实**;它解释了 v6 之后 CV↔LB 偏移的系统性坍塌。凭证类泄露无风险。

## Analysis

### 一、CV↔LB 偏移的坍塌轨迹(先验证据)

项目一直用「OOF − 0.031 ≈ Private」离线推算收益。把历次提交摊开看,这个偏移并不稳定,且从 v4 起单调收缩:

| 版本 | OOF | Private | 偏移 |
|---|---|---|---|
| v1 stack | 3.64362 | 3.61276 | −0.03086 |
| v2 clean+pp | 3.64195 | 3.60974 | −0.03221 |
| v3 clean+pp | 3.64228 | 3.60965 | −0.03263 |
| v4 clean+pp | 3.63670 | 3.60772 | −0.02898 |
| v5 F10 | 3.63474 | 3.60753 | −0.02721 |
| v6 TE-v1 F20 | 3.63192 | 3.60635 | −0.02557 |
| **v6 TE-v2 F20** | **3.62760** | **3.61226** | **−0.01534** |

偏移收缩 = OOF 比 Private 下降得快 = OOF 里混进了不能外推的成分。TE 引入后收缩加速,TE-v2 一步吃掉一半偏移。

### 二、机制:折外目标编码的「剔除自己」人工信号

`src/v6_te.py:oof_target_encode` 中,验证折某个键组 g 的编码值为

```
te(va_k ∩ g) = (S_g − s_k + α·prior) / (n_g − m_k + α)
```

其中 `s_k / m_k` 是本折落在 g 里那批行的标签和与行数。**这批行自己的标签被剔除了**,于是:

- 该组里凡是 outlier 的行,都会把自己所在折的编码值往下压;
- 因此在 train/OOF 上出现「同组内 te 越低越可能是 outlier」的**负相关**;
- **test 行没有这个结构** —— test 的标签从来就不在统计里,它拿到的是完整训练集的组率,与自身标签独立。

这就是 CV 好、LB 不好的直接来源:模型在 CV 上学到并兑现了这个关系,到线上它不存在。

注意这**不是**实现 bug。键构造、`_join` 无碰撞、`.iloc/.map` 对齐、test 侧十折平均口径,逐项复核均正确;这是折外 TE 这一做法的固有性质,只是在小组上被放大到了一级量级。

### 三、定量证据

诊断指标:**组内残差 AUC**。组内残差 = `te − 组均值`,它只随「折」变化;折划分与个体标签独立(分层只保证各折全局 outlier 率一致),因此无泄漏时它对 outlier 的判别力应恰好是 0.500。

以 `outputs/te_features_v2.npz`(α=20,seed 777 折)实测:

```
仅用组内残差(不含任何真实特征)预测 outlier 的 AUC = 0.7498
69 列中 within-group 相关 < −0.01 的有 67 列,< −0.05 的有 39 列,中位 −0.0646
```

**分键集归因**(同一份编码,按列子集分别计算):

| 键集 | 列数 | 泄漏 AUC | 组级 AUC(真实信号粗略上界) | 单模 lgb OOF |
|---|---|---|---|---|
| v1 静态键(feature_1/2/3、ref_month、月差四统计) | 36 | **0.611** | 0.830 | 3.64170(−0.00121) |
| 行为分箱交叉(auth_bin / cnt_bin / elapsed_bin) | 30 | **0.790** | 0.857 | v3 全量 3.63446(−0.00845) |
| 高基数众数键(mode_mcat / mode_city / mode_state) | 3 | **0.733** | **0.641** | v4 全量 3.64089(−0.00201) |
| 全部 | 69 | 0.754 | 0.855 | 3.63525(−0.00766) |

三条硬结论:

1. **"增益"与"泄漏"完全同源**。泄漏最轻的 v1 静态键(0.611)恰好是唯一真正转化到线上的版本(ΔOOF −0.00263 → ΔPrivate −0.00118,转化率 45%);泄漏最重的行为分箱交叉贡献了 v1→v3 的 −0.00724 OOF「增量」,而含它的 TE-v2 线上倒退 +0.0059。组内残差相关最负的 11 列,清一色是 `*_x_elapsed_bin` 与 `*_x_auth_bin`(−0.13 ~ −0.16,组中位样本数仅 39–47)。
2. **高基数众数键的人工信号强于真实信号**(0.733 > 0.641),是所有键里性价比最差的一组。
3. **`30-v6_target_encoding.md` 中"增益主要来自高基数众数列"的归因是错的**:v3(11 键、**不含**众数键)OOF 3.63446 反而优于 v2(含众数键)3.63525;众数键单独只值 −0.0008(v1 3.64170 → v4 3.64089)。真正的「增益」来自行为分箱,也就是泄漏最重的那批。

**α(贝叶斯平滑)不是解药** —— 实测:

| α | 20 | 100 | 500 | 2000 |
|---|---|---|---|---|
| 泄漏 AUC(69 列) | 0.7539 | 0.7523 | 0.7363 | 0.7127 |
| 组级 AUC | 0.8551 | 0.8527 | 0.8481 | 0.8437 |

α 把真实信号与人工信号**同比例**压向 prior,两者之比几乎不变。决定泄漏强度的是**组样本量**(人工位移 ≈ 1/(n+α)),不是平滑系数。

### 四、次级风险(方向一致,幅度小得多)

| # | 位置 | 问题 | 评估 |
|---|---|---|---|
| S1 | `elo_pipeline.py:select_features` | TOP_K=300 的特征筛选用**全量 train 标签**做,产物 `outputs/feature_importance.csv` 被 v5/v6 全部脚本复用,再在同一批行上跑 CV | 选择性泄漏,让 OOF 系统性偏乐观;近千维选 300,幅度通常在 0.0005 量级 |

| S3 | `exp1_clean_postprocess.py:63-75`、`v5_fusion.py:alpha_blend_baseline` | 后处理策略/α 在全量 OOF 上网格搜 | 同 S2,参数少、幅度更小 |

| S7 | `elo_pipeline.py:stack_ridge`、`v5_fusion.py:evaluate` | 二层用一层 OOF 做训练特征(一层 OOF 由见过本折验证行的模型产出) | Stacking 固有,业界通行,量级远小于 TE 问题 |

## Review

**当前 59 名的成绩(v6 TE-v1,Private 3.60635)不需要回滚** —— 它线上实测有效,只是它的 OOF 也含约 55% 的水分。真正的问题是**判据失效**:v6 之后 OOF 已不能用来选方案,而项目正靠 OOF 决定下一步做什么。距金牌线 0.00557 的差距,在一个被污染 0.01 量级的判据下无法收敛。

因此优先级不是「再找新信息」,而是**先把尺子校准**(P1),否则后续每一轮 A/B 都是在噪声上做决策。
